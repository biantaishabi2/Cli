## 核心组件

### 1. State Machine（状态机）

```go
// pkg/state/machine.go
type State string

const (
    StateFixRequested    State = "bot:fix"
    StatePlanDraft       State = "bot:plan-draft"
    StateNeedsDiscussion State = "bot:needs-discussion"
    StatePlanFinal       State = "bot:plan-final"
    StateImplementing    State = "bot:implementing"
    StatePRCreated       State = "bot:pr-created"
    StatePRReviewable    State = "bot:pr-reviewable"
    StatePRNeedsFix      State = "bot:pr-needs-fix"
    StateIterating       State = "bot:iterating"
    StateDone            State = "bot:done"
)

type Machine struct {
    repo  string
    issue int
    client *github.Client
}

func (m *Machine) Current() (State, error)
func (m *Machine) Transition(to State) error
func (m *Machine) CheckConvergence() (ConvergeResult, error) // 检查收敛条件（见收敛条件算法）
```

### 2. Marker（幂等）

```go
// pkg/marker/marker.go
type Type string

const (
    TypePlanDraft         Type = "BOT:PLAN_DRAFT"
    TypeDiscussionSummary Type = "BOT:DISCUSSION_SUMMARY"
    TypePlanFinal         Type = "BOT:PLAN_FINAL"
    TypePRCreated         Type = "BOT:PR_CREATED"
    TypeConvergeWarning   Type = "BOT:CONVERGE_WARNING"
)

type Marker struct {
    Type     Type
    Issue    int
    Revision int
    PR       int  // for PR_CREATED
}

func Find(client *github.Client, repo string, issue int, t Type) (*Marker, error)
func CreateOrUpdate(client *github.Client, repo string, issue int, marker *Marker) error
```

## 统一工作流设计

一个 workflow 处理所有状态，根据当前 label 决定执行哪个阶段。

### 触发条件

```yaml
on:
  issues:
    types: [labeled, opened]
  issue_comment:
    types: [created]
  pull_request_review:
    types: [submitted]
  schedule:
    - cron: '*/5 * * * *'  # 每5分钟检查讨论收敛
```

### 工作流逻辑

```
收到事件
    ↓
判断事件类型和当前状态
    ↓
├─ Issue 加 label "bot:fix"
│   └─ 执行 Draft 阶段
│       ├─ 检查 marker BOT:PLAN_DRAFT
│       ├─ 生成草案方案
│       ├─ 评论输出 + marker
│       └─ label: bot:plan-draft
│           └─ 信息不足则 label: bot:needs-discussion
│
├─ Issue 有新评论 或 schedule 触发
│   └─ 且状态为 bot:needs-discussion
│       └─ 执行 Discussion 阶段
│           ├─ 检查收敛条件
│           ├─ 未收敛：更新汇总评论
│           ├─ 轮次 ≥ 5：直接定稿 → Final Plan
│           ├─ 静默 ≥ 10min：发预警评论（"30min 内无回复将自动定稿，/hold 暂缓，/finalize 立即定稿"）
│           ├─ 预警后静默 ≥ 30min 或收到 /finalize：生成 Final Plan
│           └─ 已收敛：
│               ├─ 评论输出 + marker
│               └─ label: bot:plan-final
│
├─ Issue 加 label "bot:plan-final"
│   └─ 执行 Implement 阶段
│       ├─ 检查 marker BOT:PR_CREATED
│       ├─ 创建分支
│       ├─ 改代码 + 加测试
│       ├─ push 分支
│       ├─ 创建 PR
│       ├─ 评论输出 + marker
│       └─ label: bot:pr-created
│
├─ PR 状态为 bot:pr-created
│   └─ 执行 Self-Check 阶段（机器人自检）
│       ├─ 跑测试（单元测试 + 集成测试）
│       ├─ 检查代码规范（fmt/lint）
│       ├─ 检查 Final Plan 中的测试场景是否覆盖
│       ├─ 测试通过：label: bot:pr-reviewable（可人工审核）
│       └─ 测试失败：label: bot:pr-needs-fix（自动修复）
│
├─ PR 状态为 bot:pr-needs-fix
│   └─ 执行 Auto-Fix 阶段
│       ├─ 分析失败原因
│       ├─ 自动修复（如格式问题、简单编译错误）
│       ├─ push 修复 commit
│       ├─ 重新跑测试
│       └─ 通过则 label: bot:pr-reviewable
│
└─ PR 收到 review (changes_requested)
    └─ 且状态为 bot:pr-reviewable
        └─ 执行 Iterate 阶段
            ├─ 获取 review 意见
            ├─ 生成修复方案
            ├─ 改代码
            ├─ 跑测试
            ├─ push commit
            ├─ 评论处理结果
            └─ label: bot:pr-needs-fix（回到自检）
```

## 收敛条件算法

两种收敛路径：
- **轮次收敛**：讨论汇总更新 ≥ 5 次 → 直接定稿（信息充分）
- **静默收敛**：两阶段确认，避免人不在时误定稿

支持命令：
- `/finalize` — 人主动确认，立即定稿
- `/hold` — 暂缓自动定稿

```go
type ConvergeResult int

const (
    NotConverged    ConvergeResult = iota // 继续讨论
    ShouldWarn                            // 发预警评论
    ShouldFinalize                        // 可以定稿
)

func (m *Machine) CheckConvergence() (ConvergeResult, error) {
    // 0. 检查是否有人发了 /finalize 命令
    if m.hasCommand("/finalize") {
        return ShouldFinalize, nil
    }

    // 1. 检查是否被 /hold 暂停
    if m.hasCommand("/hold") {
        return NotConverged, nil
    }

    // 2. 轮次收敛：讨论汇总更新 ≥ 5 次，直接定稿
    summary, err := marker.Find(m.client, m.repo, m.issue, marker.TypeDiscussionSummary)
    if err != nil {
        return NotConverged, err
    }
    if summary != nil && summary.Revision >= 5 {
        return ShouldFinalize, nil
    }

    // 3. 静默收敛：两阶段
    lastComment, err := m.getLastCommentTime()
    if err != nil {
        return NotConverged, err
    }
    quietWindow := time.Since(lastComment)

    // 已发过预警？
    warned, err := marker.Find(m.client, m.repo, m.issue, marker.TypeConvergeWarning)
    if err != nil {
        return NotConverged, err
    }

    if warned != nil {
        // 预警后静默 ≥ 30 分钟 → 定稿
        warnTime := warned.CreatedAt
        if time.Since(warnTime) >= 30*time.Minute {
            return ShouldFinalize, nil
        }
        return NotConverged, nil
    }

    // 未预警，静默 ≥ 10 分钟 → 发预警
    if quietWindow >= 10*time.Minute {
        return ShouldWarn, nil
    }

    return NotConverged, nil
}
```

## 错误处理

| 错误类型 | 处理 |
|----------|------|
| Codex 调用失败 | 重试 3 次，仍失败则退出，等下次触发 |
| GitHub API 限流 | 指数退避重试 |
| 测试失败 | 评论通知，标记 bot:needs-fix，人工介入 |
| 冲突无法自动解决 | 评论通知，人工介入 |

## 安全边界

1. **只走 PR，不直接 push main**
2. **路径白名单**：默认只允许改 `src/`, `tests/` 等
3. **高风险路径**：改 `auth/infra/deploy` 时自动降级为"只提建议"
4. **权限最小化**：workflow `permissions` 精确控制

### 目标

- {{.NonGoals}}

  - {{.Evidence}}

## 3. 修复策略

- **技术方案**: {{.Solution}}
- **改动范围**: {{.Scope}}

### 文件/模块/接口
{{range .Changes}}
- [ ] `{{.File}}`: {{.Description}}
{{end}}

### 兼容性影响
- {{.Compatibility}}

### 开关/降级策略
- {{.Fallback}}

## 5. 风险与回滚

- **最坏情况**: {{.WorstCase}}
- **回滚方案**: {{.Rollback}}

## 6. 测试场景（必须）

### 6.1 复现测试
- **输入**: {{.ReproInput}}
- **前置条件**: {{.ReproPrecondition}}
- **期望输出**: {{.ReproExpected}}

### 6.2 回归测试
- [ ] 同模块关键路径: {{.RegressionPaths}}
- [ ] 上下游调用链: {{.RegressionChain}}
- [ ] 老行为不变断言: {{.RegressionAssertions}}

### 6.3 边界与异常
- [ ] 空值/缺字段/非法字段
- [ ] 超长/超大输入
- [ ] 超时/重试/幂等
- [ ] 并发/竞态
- [ ] 权限/鉴权失败路径

### 6.4 非功能（NFR）
- [ ] 性能: 热点路径不退化
- [ ] 资源: 内存/句柄/连接无泄露

---

**生成时间**: {{.GeneratedAt}}
